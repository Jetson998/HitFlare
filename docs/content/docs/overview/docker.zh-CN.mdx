# Docker 部署

如果你希望在自己的机器或服务器上运行项目，可以直接使用 Docker Compose。

## 使用当前源码启动

```bash
git clone git@github.com:Jetson998/HitFlare.git
cd infinite-canvas
cp .env.example .env
# 在 .env 中填写 HITFLARE_ADMIN_EMAIL 和 HITFLARE_ADMIN_PASSWORD
docker compose up -d --build
```

启动后访问：

```text
http://localhost:3000
```

使用 `.env` 中的管理员账号登录。

## 本地构建镜像

如果需要基于当前源码构建镜像：

```bash
docker compose -f docker-compose.local.yml up -d --build
```

## 文档站镜像

文档站位于 `docs/` 目录，按带服务端能力的 Next.js standalone 应用单独构建，不打进主应用镜像。

使用发布镜像：

```bash
cd docs
docker compose up -d
```

基于当前源码本地构建：

```bash
cd docs
docker compose -f docker-compose.local.yml up -d --build
```

## 数据说明

主应用容器使用 Node 24，同时提供前端页面、登录接口和模板接口。项目不开放用户自行注册；账号数据库中还没有管理员时，会使用以下变量创建首个管理员：

| 变量 | 说明 |
| --- | --- |
| `HITFLARE_ADMIN_EMAIL` | 首次管理员登录邮箱，必须唯一 |
| `HITFLARE_ADMIN_USERNAME` | 首次管理员展示用户名 |
| `HITFLARE_ADMIN_PASSWORD` | 首次管理员密码，首次启动必填 |

用户 UUID、邮箱、展示用户名、角色、状态和登录记录保存在 `hitflare-data` 数据卷中的 SQLite 数据库。重建容器时应保留该数据卷；数据库已有管理员后，修改环境变量中的密码不会覆盖现有密码。

画布、我的素材、生成记录、AI API Key 和 Base URL 目前仍保存在每位用户自己的浏览器本地，生成内容服务端同步留待后续实现。

## 统计分析（可选）

项目**默认不接入任何统计**：不设置下列环境变量时，页面不会加载任何统计脚本，也不会发送任何外部请求。你在自己的部署上想查看流量时，设置对应环境变量即可，无需修改代码或重新构建镜像——镜像启动时会据此生成运行期配置。

统计按「每家一个独立变量」配置：**填了谁就启用谁，可同时启用多家**（例如 GA4 + 百度一起开）。仅支持 GA4 与百度，两者都只接受 ID，脚本地址由代码固定拼接，不接受任意脚本地址或内联 JS。

| 变量 | 说明 |
| --- | --- |
| `ANALYTICS_GA4_ID` | Google Analytics 4 衡量 ID（`G-XXXX`） |
| `ANALYTICS_BAIDU_ID` | 百度统计站点 ID（`hm.js?` 后面那串 hash） |

在 `docker-compose.yml` 的 `environment` 中配置（文件内已附注释示例），下例同时启用 GA4 与百度：

```yaml
services:
  app:
    environment:
      ANALYTICS_GA4_ID: G-XXXXXXXXXX
      ANALYTICS_BAIDU_ID: e8263761cc5c32f5f7a855b8203b965a
```

或使用 `docker run`：

```bash
docker run -d -p 3000:3000 \
  -v hitflare-data:/app/data \
  -e HITFLARE_ADMIN_EMAIL=admin@example.com \
  -e HITFLARE_ADMIN_USERNAME=管理员 \
  -e HITFLARE_ADMIN_PASSWORD='替换为首次管理员密码' \
  -e ANALYTICS_GA4_ID=G-XXXXXXXXXX \
  -e ANALYTICS_BAIDU_ID=e8263761cc5c32f5f7a855b8203b965a \
  hitflare:local
```

单页应用的路由切换会自动向所有已启用的统计上报 pageview。

<Callout type="warn">
请只在你自己的站点上配置统计 ID，不要把 ID 提交进仓库；fork 或自托管本项目的用户默认不会产生任何统计。
</Callout>
