## 完整创作 Agent 用户旅程（规划记录）

完整的图片或视频创作 Agent 应在同一个对话中承接从需求到成片的全过程。用户不需要先学习提示词、模型参数或工作流节点，Agent 负责理解创意、调用创作工具、读取生成结果并继续处理后续修改。

```text
用户表达创意
  → Agent 追问必要需求
  → 生成故事 / 创作方案 / 提示词
  → 用户确认生成
  → 生成图片或视频
  → Agent 查看并理解结果
  → 用户提出修改意见
  → Agent 基于当前版本再次生成或编辑
  → 用户确认结果
  → 保存版本、素材和最终成片
```

对于视频创作，生产过程可以进一步展开为：

```text
Idea
  → Story
  → Script / Storyboard
  → Character Reference
  → Shot Generation
  → Review / Regeneration
  → Concatenation
```

- **Idea**：接收用户的一句话或模糊创意，识别主题、目标、受众和情绪方向。
- **Story**：补充人物、冲突、场景、节奏和结局，形成可讨论的故事方案。
- **Script / Storyboard**：把故事拆成场景、镜头、动作、景别、机位、台词、音效和镜头间关系。
- **Character Reference**：建立角色、商品、场景和视觉风格的参考资产，供后续镜头保持一致。
- **Shot Generation**：按镜头调用图片或视频生成工具，跟踪异步任务，并把结果绑定到当前会话和项目。
- **Review / Regeneration**：让 Agent 理解生成结果；用户可以提出“保留主体、只改背景”“人物更近一些”等自然语言修改，Agent 基于当前版本生成下一版。
- **Concatenation**：按分镜顺序合并视频片段，继续处理转场、旁白、音乐、字幕和最终输出。

这个旅程的关键是循环，而不是一次性流水线：

```text
规划 → 用户确认 → 执行 → 查看结果 → 用户反馈 → 修改 → 再执行
```

图片创作和视频创作都应把生成结果作为对话上下文中的正式产物。每一版结果需要保留来源提示词、参考资产、任务状态和版本关系，使 Agent 能够理解“上一版是什么”和“这一次只需要改什么”。用户可以在任意阶段暂停、修改方案、重新生成或回到之前的版本。

本节记录的是完整对话式创作 Agent 的目标用户旅程和调研结论，不代表当前 HitFlare 已经实现。当前已确认的创作 Agent 能力和边界仍以本文后续“已确认边界”及“当前验证”为准。

## 已确认边界

- Agent 聚焦创作目标、提示词优化与参考素材；不调用场景模板，不执行画布操作，不自动生图。
- 用户未询问时不主动推荐生成参数；用户主动询问时只给文字建议。
- 卡片底部集中操作：未修改时为“使用方案 / 修改方案”，已保存修改时为“使用方案 / 修改方案 / 还原图标”，编辑时为“取消 / 保存”。“使用方案”只带入提示词和参考图；还原沿用确认弹窗，恢复后回到未修改状态。
- 会话、消息、素材、草稿、每轮上下文与执行状态均持久化在服务端；浏览器只作为展示和编辑缓存。
- 不自动删除或截断历史。首期提供新建、切换、搜索和重命名；永久删除与素材清理规则待统一确定。

## 数据与权限

现有登录身份来自 `server/auth.mjs`。Agent 使用同一数据目录下的 `hitflare-agent.sqlite`，与账号数据库独立；参考图二进制也保存在 Agent 数据库中，便于本地与单实例部署备份。不是浏览器业务数据存储，也不代表其他模块已经完成云同步。

`threads` 保存用户归属、文档版本、会话、消息、原稿、当前方案、草稿和每轮调用上下文。`assets` 保存用户与会话归属、标题、真实媒体格式及文件内容。所有会话与素材访问均按当前登录用户校验。前端请求另带期望用户 ID，用于阻止旧标签页在账号切换后误发到新账号；这个 ID 不作为身份凭证。

消息使用 `threadId + turnId + itemId` 归属。用户消息和助手占位在同一事务中创建，结果替换对应占位。协议版本与存储版本独立，未知存储版本或损坏文档拒绝覆盖；未来迁移必须先备份。

## 执行与恢复

发送请求持久化后返回 202，模型在服务器继续运行，关闭页面不取消。SSE 只发送当前用户的数据变更通知，前端重新读取权威快照，不重复合并消息。模型回复先严格校验并落库，再发变更通知。

当前运行方式为单 Node 实例。重启时把遗留执行标记中断，不自动重新收费调用。180 秒后终止请求并记录失败；取消操作也写入状态。SDK 自动重试关闭。超长上下文不静默剪裁，渠道拒绝后保留完整记录；摘要策略待确认。

## 请求关系

用户页面从「配置与用户偏好」解析当前用户选中的文本模型渠道，只把本次渠道地址、密钥、模型和当前会话消息交给 HitFlare Agent API。服务端根据登录用户读取该会话的云端历史，把完整上下文和参考图发送到该用户本次选择的 OpenAI 兼容模型；渠道密钥只存在本次请求的内存调用链，不写入会话、数据库或返回结果。模型只返回普通文本或创作方案 JSON，服务端校验后落库，前端通过快照和 SSE 通知展示。模型请求结束后不依赖连接继续保存上下文，下一次请求由同一会话的服务端记录重新组装。

方案卡片是对话中的独立创作卡片，支持用户直接编辑目标、提示词和参考素材。普通创作只展示当前方案；只有提示词优化结果带有原始提示词时，才显示原始提示词折叠区和默认可见的优化后提示词预览，并按段落与列表呈现。保存编辑后保留原稿并显示已修改状态。唯一主操作是“使用方案”，它只将提示词和参考图带入 `/image`，不带模型、比例、清晰度和数量，也不会自动开始生成。

提示词优化通过卡片可选字段 `mode: optimize_prompt` 与 `originalPrompt` 表达；普通创作为 `mode: create`，不携带对照原文。服务端校验原文是当前会话用户输入或方案当前提示词的逐字引用，编辑接口仅接受目标、最终提示词与参考图，对照来源不由前端修改。此为现有 JSON 文档的可选展示字段，未迁移或改写已有历史；启用前已将 Agent SQLite 备份至 `.local/backups/agent-before-prompt-comparison-ov3qlkwv.sqlite`。

前端复用现有 Streamdown，以静态模式展示小标题、段落和列表，关闭额外复制或下载控件。未分段的纯文本由 `Intl.Segmenter` 在展示时按句子分段，存储内容不变。输入区不显示常驻草稿提示，自动保存和失败处理仍然可用。

顶部无当前会话时显示“创作 Agent”，有当前会话时显示会话名称，不再另占一行重复标题。点击名称在原位置编辑并选中文本，失焦或按回车即保存，没有重命名弹窗和确认按钮；中文输入法选词时按回车不提交。按 Esc 取消本次编辑，空白或未变化的名称恢复原显示且不发请求。保存期间输入只读，失败时保留编辑内容并提示，可再次聚焦、修改后失焦保存。保存沿用会话修订号校验，编辑状态按当前会话重置；长名称单行省略，悬停可查看全文，右侧新建、历史和关闭按钮保持可见。

当前提示词默认显示最高 18rem（默认 288px）的预览，超长部分仅在视觉上隐藏，预览区不启用内部滚动，滚轮继续用于浏览上下对话。只有内容超高时显示“展开提示词”；点击后在同一限高区域内启用鼠标、触控及键盘滚动，“收起提示词”返回开头并恢复无内部滚动的预览。短内容按实际高度显示，不出现展开按钮。原始提示词仍默认折叠，打开后也使用相同的预览与展开交互；内容与面板尺寸变化时重新判断是否超高。操作栏位于提示词区域外，完整提示词继续用于编辑、保存和图片页交接，不裁剪数据。卡片顶部保留图标和状态文字。

用户消息与 Agent 回复连续展示，不再在消息之间添加分隔线。Agent 顶部操作顺序为“+ 新建会话 → 历史会话 → 关闭 Agent”。

用户消息在对话面板中靠右显示，标识使用当前登录账户的用户名 `username`，长用户名省略并支持悬停查看。气泡使用浅灰色半透明圆角背景，宽度按内容自适应并限制最大宽度，上下内边距均为 12px，正文外边距归零；无参考图时不渲染空素材容器，避免额外底部留白。Agent 普通回复与创作方案卡片靠左显示，有参考素材时随用户消息保留在右侧消息块内。

创作方案使用独立白色卡片承载，顶部状态栏、正文区和底部操作区分层显示，使用圆角、细边框和轻阴影建立卡片层次；长提示词在点击“展开提示词”后才可在正文区内滚动，操作区保持在卡片底部。

输入区使用一个圆角容器：参考图预览和文本在上方，底部左侧为上传图片、选择素材，右侧为默认文本模型简称和发送按钮。名称只读取偏好设置的默认文本模型，未选择时显示“未配置模型”；长名称省略显示，悬停可查看完整名称。简称仅移除开头的 `claude-` 或 `gpt-`（忽略大小写），例如 `Claude-opus-x → opus-x`、`Claude-fable-x → fable-x`、`gpt-5.6-sol → 5.6-sol`、`gpt-6-astra → 6-astra`；其他名称原样显示，实际模型请求继续使用完整名称。

## 部署与模型依赖

- Node 24，现有登录数据库；新增服务端依赖 OpenAI SDK、Zod、file-type。
- 渠道页只维护可用渠道和模型列表；Agent 的实际对话模型只读取「配置与用户偏好 → 偏好设置 → 默认文本模型」。默认文本模型名称为 `gpt-5.6-sol`，再根据该模型与渠道的绑定关系取得接口和密钥，不从全部已拉取模型中自行选择。
- 用户选择的渠道需要支持 `/chat/completions`、JSON 对象输出和图片输入。没有可用文本渠道时只开放历史与编辑，明确显示配置提示，不回退到模拟答案。
- Agent 会按全站渠道约定规范化接口地址：用户填写域名根地址时自动请求其 `/v1/chat/completions`，已填写 `/v1` 时保持不变；失败记录会区分连接、认证、接口、模型和限流错误。
- 多实例部署需要统一任务所有权和执行恢复；不应让两个 Node 实例共用本实现的 Agent 数据库并同时启动恢复。

- `web/npm run typecheck`：通过。
- 浏览器已确认本地首页、白色主题、本地 Logo 和五项主导航；真实渠道联调确认默认文本模型 `gpt-5.6-sol` 可以返回创作方案卡片，方案已写入云端会话。
- 此前真实联调调用两次：原失败消息手动重试约 11.5 秒返回创作方案；同会话连续消息约 3.3 秒返回“已确认”，前端自动展示并恢复发送状态。两轮均落库，没有调用图片生成。
- 真实联调中发现并修复了根地址漏加 `/v1` 的问题；服务端回归测试覆盖根地址、带 `/v1` 地址、尾斜杠以及 HTTP 失败分类。未配置时仍保留历史、编辑和素材管理，发送会明确提示服务未配置。
- 本地 API 重启后，测试页的旧实时连接未立即恢复；关闭并重新打开 Agent 后已读取成功方案。部署更新后应刷新已打开的页面；这次恢复没有重新调用模型。
