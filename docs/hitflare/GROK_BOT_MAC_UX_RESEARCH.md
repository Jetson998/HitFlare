# Grok Bot Mac 版体验调研

来源是用户提供的 Grok Bot Mac 版截图。结论只记录画面里能看到的交互，以及用户当场指出的规则。没有把网页版、手机版或未出现的功能写进来。

用户判断：这套体验好，后续 Agent 创作页按这个抄，不继续在现有卡片上缝。

## 整体

窗口分成两块。左侧是历史对话，顶到窗口上沿，没有再套一层页头。右侧是当前对话，自己滚动。输入框永远留在右侧底部。

历史和对话是两个区域。滚对话时，左侧列表不动。当前要看的图或方案，也不该被对话滚走后才找得到。

## 左侧历史

顶部只有两个圆形按钮：放大镜搜索历史，加号新建对话。没有「新对话」文字按钮，也没有分组标题占第一行。

每条历史是头像、标题、一行预览。当前项用浅底标出。列表从按钮下面一直排到窗口底部附近，账号或连接入口在最下。

## 右侧顶部

当前对话的标题是一颗居中的胶囊，不是通栏浅底，也不悬浮盖住内容。打开方案全文时，这颗胶囊换成方案名；左侧出现关闭，右侧出现分享。关闭后回到原来的对话，左侧历史保持不动。

## 对话

用户的话靠右，浅灰圆角胶囊，旁边有表情、回复和更多。助手的话靠左，同样是浅灰圆角气泡，宽度随文字收，不铺满对话区。

图片生成后，先在气泡下面放一张圆角预览，左对齐，尺寸能看清画面，但不是撑满对话区的大图。点这张预览才进入全屏：深色遮罩，图片居中放大，右上是下载和关闭，图下有一行说明。多张图在全屏里并排成画廊，不叠成一条小缩略图。

## 方案卡

方案先出现在对话流里，是一张白卡片：标题、一句说明、分段正文，底部有一个文件芯片，写出方案名和「页面」。卡片不单独做大标题栏，也不跟对话抢滚动。

点开方案后，方案占满右侧对话区，不是再弹出一块小卡片。左侧历史仍在。顶部左侧关闭，中间是方案名胶囊，右侧分享。正文按文章排：大标题、导语、分节、正文。输入框仍留在这块区域的底部。

## 输入框

没写字时折成一行。左侧加号，中间是「给当前对象发消息」，右侧是语音和发送。

写了内容后，输入框长到一个固定高度，不再无限变高。文字在框内滚动。加号留在左下，语音和发送留在右下。发送是一颗实心圆按钮。

输入框上方可以出现一条建议胶囊，例如「先给我提示词方案」。它不属于输入框正文。

## 对照时不要抄错的点

- 不要把方案卡固定在输入框上方再跟对话分两套滚动。Grok 是对话自己滚，方案卡先在对话里，点开才占满右侧。
- 不要用灰边把图片撑成横条。预览保持图片自己的比例。
- 不要让卡片标题悬浮盖住上一张图。
- 历史搜索和新建对话是图标，不是一行文字按钮。
