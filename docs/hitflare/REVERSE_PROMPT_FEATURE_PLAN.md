# 反推提示词菜单功能方案

> 状态：首版已实现并接入导航，待用户进行浏览器和真实模型验收。
>
> 目标：在 HitFlare 中新增一个独立的「反推提示词」菜单，复刻参考站已经验证的产品流程：上传一张图片，选择反推模式和文本模型，流式得到一段可复制的中文提示词。

后续升级见 [视觉拆解与反推提示词升级方案](VISUAL_ANALYSIS_AND_REVERSE_PROMPT_UPGRADE_PLAN.md)：先升级图片场景分析、共享视觉事实、还原提示词与风格提取，再扩展视频。本文保留首版基线与验收边界，不代表升级能力已经实现。

## 1. 首版范围

### 1.1 建议入口

- 菜单名称：`反推提示词`
- 建议路由：`/reverse-prompt`
- 建议图标：沿用项目现有 `lucide-react` 图标体系，使用能表达扫描、识别或提示词的图标。
- 桌面导航和移动端抽屉都接入同一个导航配置；中英文导航文案分别补到现有 i18n 文件。
- 页面标题：`反推提示词`
- 页面副标题建议：`上传图片，提取可复用的绘图提示词`

以上名称是 HitFlare 的新增建议，不是现有代码事实。第一版只做独立页面，不与 Agent、图片生成、素材库或画布联动。

### 1.2 必须包含

- 单张图片输入：点击选择、拖放、表单区域内粘贴。
- 两种反推模式：`图生图通用仿照`、`文生图模仿`。
- 已配置的文本模型选择；请求必须带图片输入能力。
- 流式显示结果。
- 停止生成、复制当前结果、复制上次结果。
- 当前结果和上次结果两个展示槽位。
- 刷新后恢复输入草稿、模式、模型和两个结果（恢复结果显示为已结束，不伪造继续生成）。
- 配置缺失、图片读取失败、请求失败、用户停止等可理解的状态提示。

### 1.3 明确排除

- 不恢复原图的原始生成参数、seed、模型元数据或不可见信息。
- 不自动生成新图片。
- 不增加额外的自由文本提示词输入、温度、尺寸、数量等生成参数。
- 不做 Agent 发起、Agent 发送、画布节点、素材选择、提示词库保存、导出文件、在线历史库或批量图片。
- 不承诺“原提示词找回”或“像素级 1:1 复刻”；模型只能根据可见图像进行视觉描述。

## 2. 用户流程

### 2.1 输入图片

1. 用户进入页面，默认模式为 `图生图通用仿照`，模型使用现有配置中的默认文本模型。
2. 用户通过文件选择、拖放或在输入区域粘贴图片。
3. 只接受图片文件；一次提供多张时，过滤非图片文件并只取第一张。
4. 读取和预处理成功后展示缩略图、文件名和可选的压缩/缓存提示。再次选择图片会替换当前输入。
5. 用户可移除图片。移除只清除当前草稿，不删除当前结果或上次结果。
6. 未提供图片时，开始按钮不可用；上传失败时保留上一张有效图片。

参考站会在上传阶段做图片预处理，并将处理后的图片交给视觉模型。参考实现对处理后大于 10 MB 的图片报错；这属于参考站行为，不应在 HitFlare 静默新增一个独立限制。实现时复用 HitFlare 现有上传/图片读取限制；若现有限制不一致，再单独确认产品边界。

粘贴监听只绑定页面表单区域，不拦截全局其它输入框的粘贴。上传、替换和开始请求期间应锁定会造成竞态的控件；这是 HitFlare 的实现要求，不必复刻参考站个别控件的锁定不一致。

### 2.2 选择模式

模式选择器显示模式名称和一句说明：

| 模式 | 说明 | 结果目标 |
| --- | --- | --- |
| 图生图通用仿照 | 剥离主体，仅保留美学风格，可二次图生图通用复用 | 输出一段可替换主体的风格提示词 |
| 文生图模仿 | 高保真复刻原图，包含具体角色、动作、情节、所有细节 | 输出一段包含原图可见主体和细节的描述提示词 |

模式切换只影响下一次请求，不自动重新调用模型，也不清空已有结果。结果卡片必须记录生成时的模式，避免用户切换后误读历史文本。

### 2.3 选择模型

- 模型来源：HitFlare 现有配置中的文本模型列表和默认文本模型，不新增 API Key、Base URL 或独立渠道配置。
- 保存的是现有模型标识（包含项目已有的渠道/模型定位方式），不能只保存一个可能重复的裸模型名。
- 上次保存的模型已经被删除或取消配置时，回退到当前默认文本模型；没有可用文本模型时显示配置入口。
- 模型列表只显示被配置为文本能力的模型；但“文本能力”不等于一定支持图片输入，模型请求前应验证或在失败时给出“该模型不支持图片输入”的明确错误。
- 管理员自定义调用脚本等现有能力沿用项目权限规则，普通用户不能因此获得额外管理能力。

### 2.4 开始与流式输出

开始条件：有有效图片、没有正在上传、没有正在生成、已有可用模型配置。

开始后：

1. 若当前结果有非空文本，先把它移动到“上次结果”；空结果不覆盖有意义的上次结果。
2. 清空当前结果文本，记录本次的模型和模式，显示“正在思考与生成中，请稍候...”。
3. 向现有文本/视觉请求能力发送一条包含图片和对应模式模板的请求，按增量文本更新结果。
4. 生成中显示停止按钮；已经产生任意文本后即可复制部分结果。
5. 完成后保留换行和空白，结果可选择、复制，不做富文本渲染，不截断长文本。

### 2.5 停止、失败和再次生成

- 停止使用 `AbortController` 取消当前请求；已生成的部分文本保留，结果标记为“已停止”。
- 网络错误、上游错误、模型不支持图片等失败需要显示错误信息，并保留已经收到的部分文本；结果标记为“失败/未完成”，不能伪装成正常完成。
- 失败或停止后，用户可以重新点击开始。重新开始会按“当前结果 -> 上次结果”的规则轮换槽位。
- 页面离开、刷新或账号切换时取消活动流；刷新后只恢复已经保存的文本，不尝试在后台续接上一次请求。
- 不自动重试。错误提示可引导用户更换模型、检查配置或手动重试。

## 3. 两套模式的提示词契约

实现可以重写模板，但必须保持下面的行为契约。参考项目的完整模板来自 AGPL-3.0 项目，HitFlare 不应直接复制整段源代码或模板原文；应根据本契约重新编写自己的系统提示词，并由产品/开发共同维护版本。

### 3.1 图生图通用仿照

模型在内部分析参考图的视觉语言，最终只输出一段中文提示词。必须：

- 去除具体人物姓名、IP 角色、特定地名、故事情节和原图实际文字。
- 保留主体位置的可替换占位符，且只出现一次：

  `[在此处替换为您想要生成的主体内容]`

- 覆盖整体风格、前中后景和构图、镜头/视角、光线、色彩、媒介与材质、情绪氛围、拍摄或渲染观感、时代/文化风格、空间与透视、画面密度和留白、运动感、后期效果、具有辨识度的视觉符号等维度。
- 占位符替换后语句仍然通顺，风格描述可直接用于后续图生图。
- 只输出最终提示词，不输出分析过程、维度清单、标题、前言或寒暄。

不应把不可见的相机参数、原始生成模型参数或无法辨认的文字编造出来。

### 3.2 文生图模仿

模型最终只输出一段中文全要素描述。必须：

- 保留可见的具体主体、外观、服装、动作、表情、主体之间的关系和情节。
- 描述可读的文字、招牌、标志和符号；看不清的文字明确省略或描述为不可辨认，不能凭空补写。
- 覆盖环境、前中后景、构图、视角、空间关系、艺术风格、光线、色彩、材质、景深、动态和可见后期效果。
- 只输出最终提示词，不使用主体替换占位符，不输出分析过程、标题、前言或寒暄。
- 目标是尽可能忠实的视觉重建，不承诺能找回原图的真实 prompt，也不承诺绝对 1:1 或像素级一致。

## 4. 页面结构与交互状态

### 4.1 输入区

输入区包含：

- 图片拖放/点击/粘贴区域。
- 已选图片预览和文件名。
- 移除图片按钮。
- 模式选择器。
- 文本模型选择器。
- 开始/停止按钮：同一位置根据状态切换，图标使用现有图标库。
- 上传错误、配置错误和请求错误提示。

不要把图片输入和结果做成层层嵌套的大卡片。按 HitFlare 浅色工作台规范使用白色主体、黑色正文和轻量边界，主色只用于主要操作、进行中状态和错误/成功强调。

### 4.2 结果区

当前结果区显示：

- 标题：`反推结果`。
- 模型名称和模式名称。
- 状态：生成中、已完成、已停止或失败/未完成。
- 等待提示或流式文本。
- 复制按钮；生成中且已有部分文本时也可复制。

上次结果默认折叠，标题显示 `上次结果` 以及生成时的模型和模式；展开后独立显示文本和复制按钮。

第一版只保留当前和上次两个槽位，不做完整历史列表。每次新的非空请求最多覆盖上次槽位；这是产品行为，不是存储容量限制。

### 4.3 响应式布局

- 窄屏：输入区在上，当前结果和上次结果在下，页面自然纵向滚动。
- 有足够横向空间时：输入区约占左侧，结果区占右侧；输入区可在页面滚动时保持可见，结果文本区域独立滚动。
- 不锁定某个硬编码视口断点或精确百分比；应结合 UserLayout 和 Agent 占用空间后的实际可用宽度适配。
- 按项目桌面验收基线检查 1440×900 和 1920×1080，并补充窄屏检查，确保长提示词不会撑破布局。

## 5. 数据与持久化建议

### 5.1 保存内容

建议按当前登录用户隔离保存以下本地数据：

- `draft`：当前图片的可恢复信息（预览、名称、MIME 类型、现有图片存储键或可重建引用）。
- `current`：当前结果文本、模型、模式、状态、更新时间。
- `previous`：上次结果文本、模型、模式、状态、更新时间。
- 小型偏好：最近模型和最近模式。

业务列表、图片数据和结果文本使用项目现有 `localforage`/IndexedDB 方式，不把 base64 或大 JSON 塞进 `localStorage`。所有异步保存和恢复都要带当前用户归属；账号切换时不能把上一用户的草稿或结果显示给下一用户。

### 5.2 保存时机

- 图片预处理成功后保存草稿。
- 完成、用户停止、失败但已有部分文本时保存结果。
- 不需要每个 token 都写入本地存储。
- 移除图片时清除草稿，但保留结果。
- 刷新恢复后把活动状态重置为已结束/中断提示，不能显示仍在生成。

参考站的实现只保存 `aborted` 标记，失败状态表达不足；HitFlare 应至少区分 `completed`、`stopped`、`failed`、`interrupted`，以免用户把半截结果误认为完整答案。

## 6. HitFlare 代码落点建议

以下是给开发的边界建议，不代表文件已经存在或已实现：

- 页面：`web/src/pages/reverse-prompt/index.tsx`。
- 页面私有组件/状态：放在 `web/src/pages/reverse-prompt/`，避免把只服务此页的组件放进全局目录。
- 外部模型请求适配：放在 `web/src/services/api/`，优先复用 `web/src/services/api/image.ts` 已有的文本/视觉消息类型、模型请求配置和流式解析；不要另造一套 API Key、渠道和代理配置。
- 模型来源：复用 `use-config-store` 的模型选择、默认文本模型和渠道/模型定位方法。需要新增“支持图片输入”的能力标记时，先明确现有配置模型是否足够表达，再做最小扩展。
- 图片预处理和本地引用：复用 `web/src/services/image-storage.ts` 及现有图片工具；不把反推图片另存成一套无法清理的 base64 数据库。
- 复制：复用 `web/src/hooks/use-copy-text.ts` 的成功提示和失败处理。
- 路由：在 `web/src/router.tsx` 的登录保护用户路由下新增页面；桌面/移动导航复用 `web/src/constant/navigation-tools.ts`。
- 文案：补充 `web/src/i18n/locales/zh-CN.ts` 和 `en-US.ts`，页面显示中文时与现有项目文案风格一致。

请求消息至少要能表达：一条系统/开发者层模式指令，加一条用户消息，其中包含模式模板和一张图片。具体协议（OpenAI Responses、OpenAI Chat Completions、Gemini 或现有脚本）由现有 `AiConfig`/渠道实现决定，不在页面内写死参考站的 `/api/nova/*` 路径。

## 7. 错误与边界验收

开发完成后至少逐项验证：

1. 未配置文本模型时，页面显示配置入口，开始按钮不可用或点击后给出明确配置提示。
2. 上传非图片文件时显示“请选择图像文件”；多张图片只取第一张。
3. 图片读取失败或预处理失败时，错误可见，上一张有效图片仍可用。
4. 替换图片后不会自动发起请求；模式和模型切换也不会自动发起请求。
5. 开始后文本逐步出现，等待、停止和完成状态可区分。
6. 生成中停止，已经出现的文本保留并标记“已停止”；再次开始可正常工作。
7. 上游失败且已有部分文本时，文本保留并标记“失败/未完成”；没有部分文本时仍显示可操作的错误提示。
8. 当前结果非空时再次开始，会移动到上次结果；当前为空时不会抹掉已有上次结果。
9. 当前结果和上次结果的模型、模式标签与实际生成时一致；切换选择器不会篡改旧结果标签。
10. 两种模式分别验证占位符规则、具体主体保留规则和“只输出最终提示词”规则。
11. 复制完整文本保留中文、换行和标点；剪贴板失败时提示用户手动选择复制。
12. 刷新后恢复草稿、模型、模式和结果；恢复页面不会继续调用模型，也不会显示假进度。
13. 登出后重新登录不同用户，不能看到上一用户的草稿或结果。
14. 1440×900、1920×1080 和窄屏下，长提示词可滚动，输入、结果、按钮和状态不重叠。
15. Agent 面板打开或可用空间变窄时，页面仍能正常使用；布局不依赖一个固定的全屏双栏假设。

真实付费模型请求不属于本方案的自动验证范围，开发自测可使用用户已经配置的渠道；模型视觉能力、上游内容安全拦截和各协议的流式差异应记录为实际验收结果。
