## 3. 原方案需要修正的事项

### 3.1 AI 总开发负责全栈交付，人工逐阶段验收

原后端需求清单与协作合同的责任描述存在冲突。当前统一由 AI 总开发实现所有层，后端/前端仅表示代码和鉴权执行边界，阶段验收由用户完成：

| 工作包 | 责任 |
| --- | --- |
| 权限开发 | AI 实现权限规则、入口、菜单/路由/按钮、401/403 交互和用户切换清理 |
| 后端开发 | AI 扩展既有身份/session、AuthContext、API 鉴权、用户管理、查询/文件隔离、存储和运维 |
| 业务前端接入 | AI 完成渠道、凭据读取、资产、媒体、历史、画布等 service/store 与页面切换 |
| 联调和本地自测 | AI 验证后端接口、业务页面、权限和故障路径，并提交实际证据 |
| 人工阶段验收 | 用户对照本阶段操作清单与出口审查；通过后进入下一阶段，未通过只修本阶段 |

API 做完不会自动把浏览器 store 变成服务端权威数据。AI 必须在同一阶段完成业务前端改造，并把各 store 的取消请求、内存重置和 Blob URL 释放纳入账号生命周期。本地自测通过后仍需人工阶段验收，不能由 AI 自行宣布放行。

统一清理指的是移除旧账号内存、订阅和预览；不能在服务未交付或登录错误时，把空数组持久化覆盖未处理的旧数据。异步请求和延迟保存要捕获发起时的账号及生命周期标识，返回或落盘前复核，防止账号切换后旧结果写入新状态。

### 3.2 当前模型请求已经是混合架构

图片/视频等工作台主要由浏览器调用供应商；创作 Agent 与反推已经把本地渠道配置和 Key 交给服务器，由服务器执行。现有服务器执行不等于 Key 已加密入库，当前 Key 仍由浏览器提供。

建议首轮保持各业务现有执行位置，先统一渠道归属和凭据服务：

- Agent、反推提交 `channelId + model + 业务输入`，后端校验渠道属于当前用户，再解密使用自己的 Key。
- 图片/视频仍在浏览器执行时，可使用仅本人可读的临时 `runtime-secret`，不得持久化明文、记录日志或进入配置导出。
- 不在本轮一次性把所有模型、格式、视频轮询和自定义脚本迁往服务器。
- 将来逐业务迁往服务端执行，再关闭该业务的明文读取需求；不能在其他浏览器调用仍依赖 Key 时全局关闭接口。
- 模型拉取、渠道测试也必须明确在哪端执行，不能只改生成按钮而遗漏其他使用 Key 的路径。

新的通用模型入口是后续演进方向，不作为资产/画布服务化的强制前置重构。当前服务 API 目录已可承担执行适配，不先引入多层网关框架。

### 3.3 新旧后端模块都要加入默认租户和统一鉴权

线上结构确认：用户库只有 users/sessions，`user_version=0`；Agent 与反推库各为版本 1，均按 `user_id` 隔离，没有 `tenant_id`。

这表示既有单部署内的用户隔离有实现基础，不表示已经有租户模型。首版只增加一个默认租户及其稳定 ID，不做租户创建/切换后台。

统一 AuthContext 由既有 `auth` 服务提供，最少包含 `userId`、`tenantId`、`role`、账号状态和 session 有效期。菜单能力采用固定角色映射即可，不先开发动态 RBAC 平台。`/api/auth/me` 保留当前 `username` 字段，增加 tenant/session/permissions；无需同时把展示字段改为 `displayName`。

新增业务表必须保存 `tenant_id + owner_user_id`；Agent/反推保留既有 `user_id` 命名也可以，但必须统一由上下文派生归属，并在需要扩展租户时纳入明确迁移。不能只给新表加字段，旧媒体和任务绕过同一边界。

现有 `x-hitflare-user` / `owner` 只是和 Cookie 用户比较的账号切换保护，并没有替代 session。复审不能把它描述成已经存在“客户端指定身份”的漏洞。新接口归属仍来自 Cookie；额外身份字段如保留，仅用于一致性检查。

### 3.4 撤销 session 不等于停止后台任务和立即关闭 SSE

当前普通 HTTP 会在 session 删除后被拒绝；但后台执行的 Agent/反推任务以创建时的用户 ID 和进程内 job 继续运行。

源码可见：Agent 执行结果提交处只检查 run 状态；反推 `activeChange` 只检查取消信号和任务状态，没有复核账号是否 active。两者 SSE 在产生事件时复查 session，没有账号禁用时主动关闭空闲连接的统一机制。

建议冻结以下行为合同，再开发：

| 动作 | 建议行为 |
| --- | --- |
| 关闭页面、SSE 断线 | 不取消已成立任务，刷新只恢复快照 |
| 用户退出或 session 到期 | 停止该会话的内容推送，前端清状态；属于账号的已成立任务可继续，重新登录本人后可恢复 |
| 用户手动停止 | 先写终态，再取消连接；晚到结果不得把任务改回成功 |
| 管理员禁用账号 | 撤销所有 session，主动断开该用户事件流，阻断新的执行阶段，取消在途调用；晚到结果只留必要的失败元数据 |
| 改角色或重置密码 | 撤销旧 session、断开对应流；个人任务是否继续按同一账号任务规则处理，避免把角色变化误作资源转移 |

已发送的供应商请求可能已经计费，取消只能尽力终止，不能承诺撤销供应商费用。禁用后不继续发起反推第二轮，必须作为新增用例。此处是源码缺口，本次没有在生产禁用真实用户复现。

### 3.5 “管理员不能读内容”的保证需要说明强度

当前管理员建号和重置密码接口接受管理员填写的目标密码。即使所有内容 API 都按 owner 校验，管理员仍可能用自己设置的密码以目标用户身份登录。这说明“后台没有内容 API”和“管理员在任何情况下都无法获知内容”是不同的保证。

建议首轮定义为应用中的管理角色不能直接调用其他用户的内容/密钥 API，所有账号操作留痕。若要求管理员也不能通过重置密码进入用户账号，则需改成用户自行设置/恢复密码的流程，管理员不能得到可用于登录的临时秘密；这涉及账号恢复产品设计，应单独确认。若还要求持有服务器、数据库或加密主密钥的运维无法读取内容，需要更强的加密方案。

服务端保存 API Key 密文防止数据库直接明文泄露，不能承诺拥有服务器主密钥的人无法解密。

### 3.6 请求日志按任务/调用/输出关联，保留具体上游错误码

Agent 快照含会话和创作内容；反推快照/历史摘要含分析、初稿、最终提示词与预览。这些是本人业务内容，不能直接用于管理员列表。

管理员日志白名单应包含 taskType/taskId、callId、HitFlare requestId、业务类型、用户/租户、调用阶段/图片槽位/尝试序号、渠道 host、模型、状态、耗时、输出数量、字节数、提示词长度，以及 `executionMode` / `reportSource`。错误字段分为应用 HTTP 状态/错误码、上游 HTTP 状态、上游 code/type、供应商 request ID 和脱敏信息；400/403 等码值不能只转成中文提示后丢失。具体字段和统计合同见 [分阶段计划第 3.1.1 节](./SERVICEIZATION_PHASED_DEVELOPMENT_LOCAL_TEST_PLAN.md#311-上游错误码与任务模型调用输出关联已确认)。

本轮仅核对本地执行路径，不新增线上验收结论：`web/src/pages/image/index.tsx` 按批量 slot 调用，snapshot 中 count 固定为 1；`web/src/services/api/image.ts` 的 OpenAI 通用入口可单次 POST 携带 n，Gemini 则按 count 展开。现有图片服务还会用 `new Error(readAxiosError(...))` 转为文案；Agent 有 HTTP 分类提示，反推有 HTTP 诊断字段，但这些不等于所需的通用持久化调用日志，不能据此宣称完整的上游 code/type/request ID 已记录。

- 浏览器直连上报标为 `client_reported`；服务器执行记为 `server_observed`，都不是供应商账单。
- 一个业务任务可有多次模型调用，每次实际请求生成独立 callId；输出记录关联生产它的 callId。当前图片工作台的多图批次对应多个调用；通用入口一次 n 请求返回多图时为一个调用、多条输出，不能虚构请求次数。反推 observe/refine 分别记录；轮询、下载、上传和保存不增加生成调用数。
- 每次调用在错误转换为 UI 文案前提取上游状态、code/type 和 request ID。HTTP 200 的流内失败保留 200 与失败码/原因；无响应的断网/CORS 不补造状态码；非 JSON 响应仅保留状态及安全概括，不复制原始错误正文。已知代理响应注明来源，不推断为最终模型错误。
- 同槽位手动重试新增 callId 并保留旧错误；反推沿用重试新建任务及旧任务关联。任务创建、调用报告和输出绑定分别幂等，重放/恢复不多记调用或用量。任务数、实际调用次数、失败/未知次数、输出数和保存数分别统计，usage/费用按 callId 去重；供应商未返回为 null/“未返回”，不按图片数推算真实消费。
- 日志关联原任务 ID，不再建一份可写的全文历史副本。用户历史与管理员日志使用不同 DTO 和查询投影。
- 默认不提供提示词片段或“必要摘要”；prompt hash 也不自动开放，防止低熵内容推测。确有排障需求时再单独定其使用范围。

### 3.7 媒体、WebDAV、配置导出必须一起收口

通用媒体库不仅是文件上传接口，还包括封面、原图、生成输出、画布附件和以后从 Agent/反推保存到资产的引用。

建议新增对象采用文件系统保存字节、SQLite 保存索引和同账号引用关系。媒体 URL 走鉴权内容接口；文件名、hash 或 objectId 不构成授权。封面/原图/历史输出/画布引用都要校验同一租户和用户；checksum 去重默认限制在该用户空间。

Agent/反推已有 BLOB 可暂时保留。若用户将其参考图保存到“我的资产”，后端通过原业务的所有权查询读取并创建通用媒体引用或复制对象，不能让浏览器拿任意 objectId 声明所有权；同一次保存使用幂等键。

现有 `exportAppConfig` 把完整 config 和 WebDAV 配置直接写入 JSON；旧 WebDAV 会合并浏览器资产、画布和日志。它们不能直接用于新的多用户服务：

- 服务化切换时停用旧应用级 WebDAV 同步和合并回写。
- 配置导出剔除 API Key、WebDAV 密码；不要把 Key 改到服务器后又通过导出接口取回。
- 浏览器设备存储诊断与服务器存储统计分开；新的服务器接口建议命名为 `/api/admin/storage/*`，避免把服务器对象库叫成本地浏览器存储。
- 首轮提供部署侧一致性备份和恢复说明；WebDAV 用户界面可以后置，关闭时明确状态。
- 如开放集中 WebDAV 内容备份，需真实的加密与独立密钥边界。“不透明对象”“没有浏览按钮”不等于内容保密。

### 3.8 服务器已有数据，浏览器旧数据的归属仍不能猜

线上已经有用户库、Agent 库和反推库。本次服务化需要保护这些现存数据，不能以原文件中的“尚未上线”描述重新初始化数据库。

这不意味着要自动兼容所有旧浏览器格式。服务器 schema 升级和未归属浏览器数据认领是两件事：

- 服务端数据库按已有需求做显式版本、迁移前备份、失败停止启动；保留用户 UUID、会话/任务 ID、完整历史与消息格式。
- 固定权威数据目录，不因新发布目录切换而创建空库。不可把在线 SQLite/WAL 普通文件复制当作一致备份。
- 三个库与新增工作台库、媒体目录需要同一写入屏障或短暂维护窗口的一致备份；逐库在线备份不自动形成跨库一致事务。
- 发布回滚需要同时判断数据库版本，旧代码不能打开已升级为未知版本的库；必要时用匹配版本的数据备份恢复。
- 未归属浏览器数据不自动绑定给首次登录管理员或全部用户。是否保留、谁能认领、导入后何时清理仍待产品决定；没有明确决定不删除旧数据。
- 旧数据导入是可选工作包，不为了兼容自行加入大量解析/迁移分支。

## 4. 推荐落地架构

沿用一个 Node/systemd 服务，保留现有三个数据库的业务边界。新增工作台库保存渠道/密文凭据、偏好、资产、生成请求/输出、画布/附件、媒体索引及引用关系；审计和请求元数据可与其同库。

```text
浏览器
  ├─ 权限上下文、菜单/路由、账号生命周期
  ├─ /api/me/config、channels：用户配置
  ├─ /api/me/media、assets：媒体与资产
  ├─ /api/me/generations：用户生成历史
  ├─ /api/me/canvases：项目文档与附件
  ├─ /api/agent/*：既有创作 Agent
  └─ /api/reverse-prompt/*：新增反推业务
                 ↓
既有 auth 服务派生 AuthContext
  → 操作权限
  → tenant + owner 查询
  → 内容接口与异步结果复核
                 ↓
身份库 / Agent 库 / 反推库 / 新工作台库 / 媒体对象目录
```

新工作台库内部的媒体索引、业务引用和画布保存使用同库事务；跨库的“保存为资产”等操作用明确的幂等流程，不声称跨数据库天然原子。

当前 task jobs 位于 Node 进程内。首轮继续单实例，不把 Redis、分布式队列、多副本和自动重启续跑加入此次服务化前置条件。服务重启标记 interrupted，不自动重发付费调用。存储持久化与任务执行持久化必须分别描述。

服务就绪状态按模块明确声明；未交付接口不能用 200 空列表冒充空数据。原合同的 `501 + SERVICE_NOT_READY` 可用于明确的占位接口；实际切换在接口和业务前端闭环都通过后进行。401/403 不回退到旧共享数据，已切为服务端权威的模块遇到网络错误也不自动切回共享 store。

现有反推已有公开地址、DNS 解析和禁止重定向保护；Agent 当前 URL 校验只验证协议和 URL 结构，没有同等的私网地址保护。新增共享服务器出站逻辑应复用成熟库及反推已有策略，把 Agent 纳入同等保护；本次未探测内网或构造利用请求。
