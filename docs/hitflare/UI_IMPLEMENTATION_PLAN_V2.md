# HitFlare 前端 UI 统一方案 · V2

状态：根据用户对 V1 的反馈修订。本轮先交付本文，再按用户“先反馈完整方案 md，然后继续开发”的授权实施。本文描述设计目标；实际检查结果另记在 pending-test，不将方案等同于已验收。

## 1. 目标与设计判断

光引 HitFlare 是图片创作工作台。界面以作品、提示词和操作为核心，采用白色主体、黑色正文、紧凑工具栏与清楚的主次关系。科技感通过对齐、密度、状态反馈和内容质量体现。

参考 HitFrame 的操作组织、素材管理和折叠设置，结合 HitFlare 的浏览器本地资产、直连 API、生成记录与 Agent 重新设计。品牌 Logo、口号和已确认的品牌素材继续使用。

本轮对反馈的处理：

| 用户反馈 | 判断 | 采用方案 |
| --- | --- | --- |
| 图片创作左右自动扩充，是否应限制最大宽度 | 不应给创作工作区套统一最大宽度 | 工作区占满可用空间，设置和记录控制宽度，结果区伸缩 |
| 其他页面在宽屏下也被限制 | 资产、灵感、管理表格同样需要利用宽屏 | 页面没有统一最大宽度；网格增加列数，表格扩展 |
| 左右固定 24px 太死 | 边距应在窄屏、桌面、宽屏间连续变化 | 同一布局容器内共用自适应边距，最小 16px、随宽度按 2% 增长、最大 48px |
| 常规页面与导航是否对齐 | 应对齐外层内容边界 | Logo 容器、页面标题、工具栏和网格使用同一条左基准线，页面右操作与导航右侧共用右基准线 |
| 间距、标题、说明、正文和页签基本认可 | 保留已认可层级 | 标题 18px、说明 13px、正文与页签 14px，避免继续改动方向 |
| 搜索、筛选、普通按钮和层级先做出来再调 | 先交付可操作的第一版 | 统一基础尺寸与语义，在本地真实页面验收后微调密度和细节 |

## 2. 页面宽度与对齐

### 2.1 外层页面

常规页面和导航共享可用空间。桌面 Agent 打开后，其占用宽度从主工作区扣除；响应式布局根据主工作区的实际宽度变化。应用总宽度不足 1100px 时，Agent 使用右侧覆盖面板，宽度不超过屏幕，避免把主页面挤到不可用；不改变已保存的面板宽度。

```css
/* W 为主工作区宽度，不含右侧 Agent。 */
padding-inline: clamp(16px, 2cqi, 48px);
width: 100%;
min-width: 0;
```

不设 1280px、1440px 等全站最大容器。这里的 48px 只限制外侧留白，不限制内容继续扩展。

| 主工作区宽度 W | 单侧边距 | 常规页面实际内容宽度 |
| ---: | ---: | ---: |
| 390px | 16px | 358px |
| 1024px | 20.48px | 983.04px |
| 1440px | 28.8px | 1382.4px |
| 1920px | 38.4px | 1843.2px |
| 2560px | 48px | 2464px |

以上为布局计算示例，尚不代表所有宽度均经过浏览器验收。对齐以容器边界为准，不通过逐个文字或图标的负 margin 修补。

### 2.2 局部内容宽度

页面外层扩展，不代表所有内容都拉成长行：

| 内容 | 宽度策略 | 原因 |
| --- | --- | --- |
| 图片结果区、资产网格、灵感网格、用户表格 | 使用全部可用空间 | 宽屏用于展示更多作品和信息 |
| 常规说明文字 | 最大约 70 个字符宽度，仍左对齐 | 避免单行过长影响阅读 |
| API、代理等单列表单 | 最大 640px | 输入位置稳定；说明和状态仍可在页面中组织 |
| WebDAV 成组表单 | 最大 800px | 容纳相关字段与操作 |
| 偏好设置 | 随可用宽度采用 1 / 2 / 4 列 | 宽屏下提高利用率，不把整页限制到 640px |
| 登录 | 独立的最大 400px 表单 | 单一任务使用聚焦布局 |
| 搜索 | 240–380px 范围内伸缩，空间不足时占满一行 | 不挤压筛选，也不拉成长条 |

### 2.3 导航

- 顶部高度 56px；菜单文字 14px、图标 16px，普通图标按钮外框 32px。
- 保留已验收 Logo：图片高度 42px、上移 4px；此项仅用于图片内部字标对齐。
- 主工作区不足 1100px 时收纳主菜单，避免菜单、Logo 和账户相互挤压。
- 不足 640px 时，主题、语言等辅助工具收进“更多操作”；保留菜单、Agent 和账户入口。
- 触屏扩大操作命中区域；菜单与弹层不能超出可用屏幕。
- 首页、图片创作、我的资产、创作灵感、配置仍为主入口；管理员附加用户管理。视频和画布旧路由继续保留。

## 3. 页面间距和文字

| 项目 | 基线 |
| --- | --- |
| 常规页面上下间距 | 顶部 20px、底部 24px |
| 标题与说明 | 4px |
| 页头与工具栏 / 页签 | 16px |
| 工具栏与内容 | 16px |
| 独立分组 | 24px |
| 同组内容 | 12px 或 16px |
| 卡片网格间距 | 16px |
| 同组按钮间距 | 8px；图标与文字 6px |
| 页面标题 | 18px / 26px，字重 600 |
| 分组、弹窗和抽屉标题 | 16px / 24px，字重 600 |
| 正文、导航、一级页签 | 14px / 22px |
| 说明、标签、搜索、筛选、普通按钮 | 13px / 20px |
| 日期、计数、辅助信息 | 12px / 18px |

说明和标题允许自然换行，不固定高度裁切。不在标题与网格之间反复叠加 padding、margin 和空白分隔区。沿用现有字体栈及 lucide 图标，默认描边 2px；不新增字体下载或全站字距。

首页品牌标题独立使用桌面 48px / 60px、窄屏 32px / 42px；区域标题 24px / 32px。工作台不沿用首页大标题。

## 4. 色彩、边界、圆角和状态

| 用途 | 规则 |
| --- | --- |
| 页面和卡片主体 | 白色；避免整页灰底、点阵和装饰性大渐变 |
| 标题和正文 | 使用现有黑色系 token；说明为次级中性色 |
| 品牌橙金色 | 用于 Logo、品牌图像，不把正文改为橙色 |
| 主操作 | 蓝紫色 `#6252E8`，悬停 `#5141D5`，浅色主题下白字 |
| 选中态 | 小面积浅底或指示线，文字保持高对比；列表弹层沿用集中主题 token |
| 边框 | `#E4E6EC`，1px；只用于输入、必要分栏及卡片边界 |
| 局部浅底 | `#F8F9FB`，用于悬停、占位或紧凑分组 |
| 圆角 | 控件 8px，内容卡片 12px，弹窗 16px |
| 阴影 | 普通卡片默认无阴影；主按钮轻阴影；弹层使用正常浮层阴影 |

选中、悬停、加载、禁用、错误和键盘焦点必须可区分。复用 Ant Design 的状态实现，保留可见的键盘焦点，避免新增复杂动画。空状态用图标、说明和必要操作，不叠加大块灰底或装饰性虚线框。

浅色是本轮视觉主线。保留深色主题，通过集中 token 维持文字、表单和弹层可读；画布继续使用 canvasThemes，不用工作台白底覆盖画布主题。

## 5. 搜索、筛选与按钮第一版

### 5.1 控件尺寸

| 控件 | 桌面尺寸 | 补充 |
| --- | --- | --- |
| 普通按钮、搜索、Input、Select | 高 32px | 字号 13px，圆角 8px |
| 分段筛选 | 总高 32px | 内侧 2px，选项高 28px；外侧不再增加一圈 padding |
| 可点击的分类、筛选标签 | 32px | 与工具控件一致；长标签允许换行 |
| 非交互信息标签 | 约 22px 单行 | 仅承载分类、数量和状态 |
| 表格、卡片紧凑图标操作 | 28px | 必须有名称或 Tooltip；触屏扩大命中区域 |
| 生成、登录提交 | 40px | 同一操作区突出主要提交 |
| 首页品牌按钮 | 44px | 仅限品牌区域 |
| 图片比例预览选项 | 保留较大图示区域 | 需要显示比例示意，不压缩成普通 32px 文本按钮 |

触屏常用控件至少 40px，输入文字 16px；窄屏布局调整与触屏命中范围分别处理，不能仅根据宽度推断设备输入方式。

### 5.2 操作层级

| 层级 | 外观 | 典型用途 |
| --- | --- | --- |
| 主操作 | 实底蓝紫，浅色主题白字 | 导入资产、生成、新建用户、保存表单 |
| 次操作 | 白底细边框、黑字 | 新增资产、取消、从资产选择 |
| 轻操作 | 透明底，无常驻边框，轻微悬停 | 导出、刷新、复制、编辑、查看 |
| 危险操作 | 红色文字，沿用确认步骤 | 删除、清理、禁用等 |

每个独立操作区突出一个主要目标。页面操作、工具筛选、卡片动作不抢同一视觉权重；使用已有功能语义，不为按钮美化改变操作结果。

### 5.3 搜索与筛选排列

- 资产页：上方标题与主操作；下一行左侧类型筛选、右侧搜索，两者垂直居中。
- 灵感页：上方标题与计数；下一行显示已选条件与清空、右侧搜索；下方为分类标签与内容网格。
- 搜索可清空，沿用原有搜索规则；筛选保留已选状态与空结果提示。
- 空间不足时按自然顺序换行，搜索占满一行，不用横向滚动藏起页面操作。

## 6. 各页面的完整落地范围

### 首页 `/`

顺序为品牌、创作灵感、场景。保留品牌示意图、已有灵感内容和三个场景入口。品牌区上下间距 48px，内容区域上下间距 32px。外层使用流式边距；长标题和说明在内部控制行长；卡片网格随宽度增列。少量场景卡片保持正常卡片尺度，不因只有三个项目而拉成超宽横幅。

### 图片创作 `/image`

不重复显示页面标题，仅保留“图片生成 / 场景模板”两个一级页签，总高 44px。图片生成仍为统一提示词与可选参考图输入，不恢复文生图 / 图生图子页签。

| 主工作区可用宽度 | 设置 / 结果 / 记录 |
| --- | --- |
| 至少 1440px | 400px / 自适应 / 300px |
| 1100–1439px | 360px / 自适应 / 280px |
| 不足 1100px | 设置与结果上下排列，记录从按钮打开抽屉 |

三栏外框占满工作区。设置、结果和记录内部使用一致的 20px 分组留白；页签左边界使用导航同一外层边距。工作台内部面板边界由分栏决定，无须把每个面板内标题都硬对齐 Logo。

生成设置继续收纳为摘要入口和弹层。统一其中模型选择、数量、清晰度、比例与提交控件，保留比例示意图必要大小。场景模板的槽位、变量、提示词预览、结果操作和右侧记录一起检查。生成接口、自动保存资产和记录的行为保持既有逻辑。

### 我的资产 `/assets`

页头左标题与说明，右侧依次为轻操作导出、次操作新增、主操作导入。筛选和搜索在下一行。内容网格最小单元 240px、间距 16px，使用 auto-fill 增列；缩略图不拉伸，详情保持原始比例。覆盖新增 / 编辑、资产选择、预览、详情、删除确认、分页和空状态。

### 创作灵感 `/prompts`

标题左对齐。内容可用宽度至少 960px 时采用 200px 筛选栏与自适应网格，卡片最小 240px、间距 16px；不足时筛选栏放在内容上方，支持折叠。筛选默认可见，搜索、已选数量和清空入口保持容易找到。覆盖模板分类、多标签、详情、复制、收藏、加载和无结果状态，不新增上传功能。

### 配置 `/config`

标题和说明与资产、灵感一致；导入 / 导出位于页头。渠道、本地代理、偏好、灵感来源、WebDAV、本地存储保留现有信息结构，页签约 40px 高。

页面外层伸缩；局部表单按第 2 节限制行长。偏好按内容可用宽度不足 560px 一列、至少 560px 两列、至少 1200px 四列排列。渠道和灵感来源卡片的辅助动作改为轻操作。配置浮窗、渠道编辑、添加模型、脚本编辑、来源编辑和引导一起检查，不改 API Key、推荐模型或引导触发逻辑。

### 用户管理 `/admin/users`

统一左标题和说明，右侧主操作。表格占用可用宽度，13px 正文、自然行高；按钮和内容不挤压，窄屏在表格内部滚动。新建、编辑、密码重置、启用 / 禁用及其弹窗沿用现有权限与账号逻辑。

### 登录 `/login`

白底、最大 400px 表单、内部 24px 留白；标题 18px、说明 13px、输入与提交 40px。检查错误提示、密码显示和加载态。该页是聚焦表单，不采用列表页铺满策略。

### 全局入口和保留路由

统一导航、移动菜单、账号、Agent 开关、配置浮窗和共享选择器。Agent 打开后重新按主工作区宽度布局。`/video`、`/canvas` 保留访问，检查共享主题变更造成的影响；不重排其业务流程，不重新加入主菜单。

## 7. 实现方式与范围边界

1. Ant Design 颜色、控件和弹层 token 集中在 `web/src/lib/app-theme.ts`；共享页面几何与基础排版放少量全局样式。
2. 页面专用布局留在各页面，复用现有 hooks、store 和组件，不增加无实质逻辑的转发组件。
3. 容器响应式优先使用 CSS container queries，不新增窗口监听状态去重复计算列数。
4. 本轮不改变账号权限、渠道请求、数据持久化、模板编译、付费生成、超时、并发和重试边界。
5. 保留当前工作区其他改动，按规范核查此前已写入的 UI 改动后补齐；不盲目回滚，不以整个目录覆盖文件。
6. 按项目要求不执行语法检查、typecheck 或构建；通过当前本地服务做浏览器布局与交互检查。本地地址统一为 `http://localhost:3000/`。

## 8. 实施顺序

1. 交付完整方案与文档入口，再开始代码工作。
2. 核对共享主题、导航和布局容器，修正残留最大宽度、固定边距和高度叠加。
3. 覆盖所有主菜单页、登录及用户管理的页头、搜索、筛选和按钮；检查各自弹窗与抽屉。
4. 检查桌面、宽屏、窄屏和 Agent 打开后的布局，以及控件主要交互状态。
5. 将实际变更和检查证据写入 pending-test，将仍需人工或真实数据验证的事项写入 todo；Changelog 记录版本级归纳。
6. 提交本地验收入口和逐页覆盖表。对未验证状态明确标注，由用户根据第一版实物继续微调。

## 9. 验收要求

| 检查项 | 通过标准 |
| --- | --- |
| 宽屏利用率 | 页面没有统一固定最大宽度；网格随可用宽度增列，图片结果区扩展 |
| 左右对齐 | 常规页面标题、工具栏、网格与导航容器共用两侧边界 |
| 控件高度 | 桌面搜索、筛选、普通按钮最终外框约 32px，无重复 padding 叠加 |
| 文字层级 | 常规页面标题 18px、说明 13px；图片页只有两个一级页签 |
| 主次按钮 | 主操作突出，次操作和辅助动作可区分，同组高度一致 |
| 响应式 | 窄屏页头 / 工具栏换行；导航可收纳；页面无横向溢出；Agent 不挤坏页面 |
| 图片与卡片 | 图片保持比例，失败时有回退；正常内容、空状态和无搜索结果均可用 |
| 交互 | 筛选、清空、展开 / 折叠、弹窗开关和菜单可操作，不改业务语义 |
| 主题与可访问性 | 浅色主线与深色主要控件可读，焦点可见，图标操作有名称，触屏点击范围足够 |
| 检查真实性 | 记录实际 DOM 视口和可用宽度；未登录页、真实生成、真机触屏等未覆盖项单独列出 |

PC 横屏是主要验收基准，优先 1440×900 与 1920×1080；390px 窄屏只作为补充，不以竖向长屏判断桌面密度和三栏布局。工具受浏览器缩放或最小尺寸限制时按实际值记录，不能把请求的尺寸当成已检查尺寸。使用独立验收页，不关闭或操作用户现有页面，检查结束恢复尺寸设置。付费 AI 生成和用户数据写入不作为本轮视觉检查的默认步骤。
